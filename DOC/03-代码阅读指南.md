## 入口装配顺序（`main.ts`）

顺序是刻意的，反了会造成"刷新被弹回登录页"：

1. `createApp` + `createPinia`，注册 pinia；
2. `useAuthStore(pinia)` 并调用 **`auth.restore()`**（从 sessionStorage 恢复令牌，
   只读本地、不发网络请求）；
3. `app.use(router)`（守卫会读 `auth.ready` / `auth.token`）；
4. `app.use(naive)`、`app.mount("#app")`。

> **为什么 `restore()` 必须在 `use(router)` 之前**：路由守卫首次导航时若看到
> "未登录"（令牌其实还在），用户每次刷新都会被弹回登录页，还带一次闪烁。

## 路由与守卫（`router/index.ts`）

- `createWebHistory("/admin/")`：必须与 vite 的 `base: "/admin/"` 一致；
  用 hash 路由会退化成 `/admin/#/users`，与 Go 侧已实现的 SPA 回退不符。
- 前置守卫 `beforeEach`：
  - `meta.public`（登录页）直接放行；
  - 无 token → 跳登录页，并用 `redirect: to.fullPath` **保留原地址**；
  - 有 token 放行。
- 后置守卫 `afterEach`：按 `meta.title` 设置 `document.title`。
- 兜底路由 `/:pathMatch(.*)*` 重定向 `/overview`（避免白屏"系统坏了"的错觉）。

## 认证 store（`stores/auth.ts`）

三条核心纪律（每条对应一个真实故障，见文件头注释）：

1. `audience: "web"` 显式传参；
2. 令牌只存 `sessionStorage`；
3. 过期静默刷新并重放，刷新失败才登出。

`client()` 返回带 `getToken` + `onUnauthorized` 的共享客户端；`refresh()` 刻意
**不抛异常**而返回 `string|null`，供客户端判定"这次 401 是否可挽救"。

## REST 客户端（`packages/api/src/index.ts`）

- **只暴露 `request`**（外加原始 `send`）：错误处理/刷新/请求头只有一份实现，
  接口再多也不膨胀。
- 类型**全部来自契约**（`schema.gen.ts`）；本文件不再手写与契约同名类型。
- `APIError` 是唯一抛出的错误类型，按 `code` 分流。
- `isBinaryBody`：Blob/FormData/ArrayBuffer 原样发送，避免分片被 JSON 序列化。

## 门禁脚本（`scripts/`）

- `lint-contract.mjs`：契约门禁——手写 fetch、手写同名 DTO、生成物过期三类失血点。
- `check-frontend-rules.mjs`：前端纪律 7 条（R1~R7），只钉"写错不报错、只会静默做
  错事"的点。
- `gen-csharp.mjs`：解析契约到 C# 模型；`desktop/` 不存在时仅校验链路、退出 0。

> 各门禁的完整规则、破坏后果与通过输出见 06-测试文档。

## 阅读建议

1. 从 `main.ts` → `router` → `stores/auth.ts` 走通认证闭环；
2. 读 `packages/api/src/index.ts` 理解请求/错误/刷新；
3. 逐个看 `views/` 如何使用 `auth.client()` 调接口；
4. 需要改接口时，先改契约 → `pnpm gen:api` → `pnpm check:api`。
