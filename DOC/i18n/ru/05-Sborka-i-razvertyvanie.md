# Сборка и развёртывание

> Полный путь: от нуля до полной сборки и встраивания артефакта на сервер. Дисциплина в начале: **сначала `pnpm build`
> затем компиляция Go** — иначе embed захватит старый артефакт (тихо неверная версия).

## 1. Требования к окружению

| Инструмент | Версия |
|---|---|
| Node.js | ≥ 20 (в CI 22) |
| pnpm | ≥ 9.15.9 (рекомендуется точная версия из lockfile) |
| Go | серверная часть (≥ 1.x) — для embed артефакта |

## 2. Установка зависимостей

```bash
pnpm install --frozen-lockfile
```

`--frozen-lockfile` гарантирует, что устанавливаемые версии полностью совпадают с `pnpm-lock.yaml` (так же и в CI).

## 3. Разработка

```bash
pnpm dev:admin
```

Запускает Vite dev-сервер (порт **5174**), `/api` проксируется на `http://127.0.0.1:8080`
(задаётся в `vite.config.ts` секцией `server.proxy`, напрямую к локальному серверу, та же форма источника, что и в production).

## 4. Production-сборка

```bash
pnpm build
```

Эквивалентно `pnpm --filter @netdisk/admin build` (`vite build`), артефакт выводится в
**`apps/admin/dist`**.

Ключевое поведение сборки (`apps/admin/vite.config.ts`):

- `base: "/admin/"` — ссылки на ресурсы начинаются с подпути;
- `outDir: "dist"`, `emptyOutDir: true`;
- `target: "es2021"` — нижняя граница браузеров (совместимость со старыми ядрами WebView WeCom/DingTalk);
- в production закрыт sourcemap (чтобы исходный код/пути интерфейсов не попадали в релиз);
- имена файлов ресурсов с хешем содержимого (`assets/[name]-[hash].js`) → предпосылка долгого кэширования.

## 5. Контракт и гейты (рекомендуется перед сборкой)

```bash
pnpm gen:api       # после изменения контракта — перегенерировать типы
pnpm check:api     # гейт согласованности артефакта с контрактом (двусторонний diff)
pnpm -r typecheck  # проверка типов по всему репозиторию
pnpm check:rules   # дисциплины фронтенда (7)
```

CI перед сборкой поочерёдно выполняет `check:api → typecheck → check:rules`; любое звено — красный.

## 6. Встраивание артефакта на сервер (ключевой шаг)

1. В `web-com` выполнить `pnpm build`, получить `apps/admin/dist`;
2. Скопировать `apps/admin/dist` в серверный `internal/webui/dist/admin/` (имя каталога неизменно,
   от него зависит `go:embed`);
3. Скомпилировать Go-бинарник — после этого `/admin` предоставляется через серверный `embed`, тот же источник с API.

> ⚠️ Ошибка порядка (сначала go build, потом pnpm build) приведёт к тому, что сервер по-прежнему встроит старый admin-артефакт;
> перед публикацией в production обязательно проверить, что `/admin/index.html` — новая версия.

## 7. Быстрая справка по форме развёртывания

- Один порт: фронтенд и API предоставляются одним Go-бинарником, тот же источник (Nginx делает только TLS и разделение трафика, статику не раздаёт).
- Подпуть: admin монтируется на `/admin/`, SPA-фолбэк реализован в Go через `webui.Handler`,
  дополнительный rewrite не нужен.

> Три «жёстко связанные с развёртыванием» конфигурации (vite `base` / history / `outDir`) и последствия белого экрана см.
> в 04-Arhitektura«Форма развёртывания».

## 8. Проверка артефакта

```bash
# минимальная проверка, что артефакт можно встроить через embed (та же, что в CI)
test -f apps/admin/dist/index.html || (echo "артефакт admin отсутствует" && exit 1)
```
