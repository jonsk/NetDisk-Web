# Тестовая документация

> В этом репозитории **не используется браузерный тест-раннер**. Вместо этого дисциплины, которые можно проверить по тексту,
> оформлены как статические гейты без зависимостей, которые можно запускать прямо в CI, и каждый из них «нарушил — красный». Гейты **не могут**
> заменить ручную приёмку (интерактив, стили, реальные устройства) — нужны оба, они дополняют друг друга.

## I. Обзор автоматических гейтов

| Гейт | Команда | Что делает |
|---|---|---|
| Согласованность контракта | `pnpm check:api` | Двусторонний diff артефакта с `openapi.yaml` + lint рукописного fetch/DTO |
| Lint контракта | `pnpm lint:contract` | Та же lint-часть |
| Проверка типов | `pnpm -r typecheck` | Проверка типов всего репозитория в строгом режиме vue-tsc/tsc |
| Фронтенд-дисциплины | `pnpm check:rules` | Статическая проверка 7 дисциплин |
| Сборка | `pnpm build` | Компиляция артефакта + проверка существования `dist/index.html` |

**Порядок в CI** (`.github/workflows/ci.yml`):
`install(frozen) → check:api → typecheck → check:rules → build →`
проверка артефакта.

## II. Гейт контракта (`check:api` / `lint:contract`)

Скрипт `scripts/lint-contract.mjs`, защищает от трёх видов «тихого разрушения единого источника контракта»:

1. **Рукописный fetch**: появление `fetch(` вне `packages/api` — ошибка: запросы должны сходиться
   к клиенту, чтобы тип/ошибка/обновление имели одну реализацию.
2. **Рукописный DTO с тем же именем**: в `packages/api` нельзя `interface/type` с тем же именем, что у сгенерированной модели
   (нужно `export type X = Schema["X"]`, следует за изменениями контракта).
3. **Устаревший артефакт** (`--check-generated`): после перегенерации посимвольное сравнение с закоммиченным — расхождение значит,
   изменили контракт без перегенерации или правили артефакт руками.

Вывод при прохождении: `Гейт контракта пройден: fetch свёрнут, нет рукописных DTO, артефакт совпадает с контрактом`.

## III. Фронтенд-дисциплины (`check:rules`)

Скрипт `scripts/check-frontend-rules.mjs`, 7 дисциплин, каждая фиксирует места «пишется неверно, ошибки нет, а тихо
делается не то»:

| Правило | Точка проверки | Последствие нарушения |
|---|---|---|
| R1 | Вход admin с `audience="web"` | Вход успешен, но все интерфейсы дают 403 |
| R2 | Токен только в sessionStorage (запрет localStorage) | Долговременное хранение учётных данных на общей машине |
| R3 | Охранник при отсутствии входа переходит на страницу входа и сохраняет исходный адрес (redirect) | После входа возвращают на главную, теряется исходная страница |
| R4 | При 401 тихое обновление и **повтор один раз** (doFetch дважды) | Только обновление без повтора = всё равно ошибка |
| R5 | Сначала `auth.restore()` в точке входа, потом монтирование маршрутов | Каждое обновление выбрасывает на страницу входа |
| R6 | Защищённый API нельзя открывать напрямую через `href/window.open` | Без токена 401 / токен попадает в историю браузера |
| R7 | В панели нельзя напрямую использовать глобальные SDK платформы (wx/dd) | Зависимость от внедряемых объектов платформы, не чисто Web |

Детали реализации: перед проверкой сначала `stripComments` снимает комментарии (чтобы пример-строка в комментарии не давала ложное срабатывание),
у каждой правила — обратная проверка (двойная проверка существования + семантики).

Вывод при прохождении: `Всё пройдено: 7 дисциплин фронтенда.`

## IV. Проверка на «домашней странице» (`gen:csharp`)

Хук генерации C#-моделей десктопа `scripts/gen-csharp.mjs`:
- всегда разбирает контракт и делает полное отображение (цепочка постоянно проверяется реальным контрактом);
- при отсутствии `desktop/` печатает причину пропуска и **выходит с 0** (не красный из-за отсутствия десктопа);
- при наличии пишет `Generated/Models.g.cs` и делает посимвольное сравнение (можно использовать в CI).

## V. Чек-лист ручной приёмки

То, что гейты не покрывают и нужно проверить вручную:

- **Замкнутый контур входа**: вход → обзор; выход → страница входа; обновление страницы не выбрасывает обратно.
- **Тихое обновление при истечении токена**: вручную сделать access token просроченным, проверить автоповтор при 401 и восстановление без ощущения.
- **Поведение охранника**: доступ к защищённому маршруту без входа → перенаправление на вход с исходным адресом, после входа возврат на исходную страницу.
- **Пользователи/отделы**: создание учётной записи, смена роли, отключение (повторное подтверждение), ошибка конфликта уникальности в поле ввода,
  поиск и пагинация на сервере.
- **Управление пространствами**: сохранение квоты/порога предупреждения, заморозка/разморозка, отзыв (подсказка, что файлы не удаляются),
  использование только для чтения без ручного изменения.
- **Лимит 429**: при слишком частых неудачных входах подсказка «повторите попытку позже».
- **Реальные устройства/браузер × разрешение**: в основном браузер настольного ПК, с учётом старых ядер.

> Интерактив, стили, поведение на реальных устройствах — слепая зона гейтов; обязательно пройти «Чек-лист ручной приёмки» перед мержем.
