# Архитектурный документ

> Фиксирует архитектурные решения и проектные соглашения этого репозитория (web-фронтенда). Контракт, компоновка, цель сборки тесно связаны с бэкендом.

## 1. Форма репозитория

- **pnpm workspace с единой целью сборки**: `apps/*` + `packages/*`.
- Community-версия содержит только админ-панель: без H5-рабочего стола, без интеграции с IDP, без журналов аудита.
- Контракт **vendored** в `DOC/api/openapi.yaml` этого репозитория (авторитетный источник в серверном репозитории, три места для синхронизации:
  сервер / web / desktop).

## 2. Выбор технологий (ключевые решения)

| Аспект | Выбор | Причина |
|---|---|---|
| Фреймворк | Vue 3 (`<script setup>`) | Композиционный API, зрелая экосистема |
| Сборка | Vite 5 | Быстро, артефакт можно кэшировать по хешу |
| Состояние | Pinia | Рекомендация официальная для Vue 3 |
| UI | Naive UI | Дружит с TS, по требованию |
| Роутинг | Vue Router 4 (History) | Совместно с SPA-фолбэком Go |
| Типы | TS strict + vue-tsc | Типовая дисциплина закрепляется гейтами |
| Управление пакетами | pnpm | workspace + строгие зависимости |
| Контракт | openapi-typescript | Единый источник для генерации моделей по веткам |
| Инструменты | node ≥ 20, pnpm ≥ 9.15.9 | CI и локально одинаково |

## 3. Форма развёртывания (встраиваемый фронтенд)

Фронтенд **не имеет отдельного статического сервера**: артефакт после `pnpm build` копируется в серверный
каталог `internal/webui/dist/`, предоставляется через Go `embed`, тот же источник и один порт с API.

Отсюда вытекают три **жёстко связанные с развёртыванием** конфигурации (изменил — белый экран):

1. **vite `base: "/admin/"`**: фронтенд монтируется на подпуть `/admin`, ссылки на ресурсы должны начинаться с этого,
   иначе 404 (белый экран + куча 404 в консоли).
2. **`createWebHistory("/admin/")`** совпадает с `base`; на Go уже реализован SPA-фолбэк.
3. **`outDir: "dist"`**: имя каталога нельзя менять, иначе `go:embed` не найдёт; gen-скрипт копирует
   `web/apps/admin/dist` в `server/internal/webui/dist/admin`.

**Дисциплина порядка сборки**: сначала `pnpm build`, затем компиляция Go — иначе embed захватит старый артефакт (тихо неверная версия).

## 4. Механизм единого источника контракта

```
DOC/api/openapi.yaml
        │  pnpm gen:api (openapi-typescript)
        ▼
packages/api/src/schema.gen.ts   ← артефакт, правка запрещена
        │  pnpm check:api (lint-contract --check-generated, двусторонний diff)
        ▼
используются все модели контракта / все типы интерфейсов
```

- Точки входа типов `Schema` / `Operations` / `Paths` — все из артефакта.
- Три жёстких ограничения `lint:contract` (рукописный fetch, рукописный DTO с тем же именем, устаревший артефакт) принуждают
  запросы сходиться в клиент, гарантируя, что «единый источник контракта» не обходится (детали реализации см. 06-Testovaya-dokumentaciya«Гейты контракта»).
- `gen-csharp` генерирует C#-модели десктопа из той же копии контракта, обеспечивая согласованное понимание по веткам.

## 5. Обязанности модулей и слои

```
views/ (страницы: вход/обзор/пользователи-отделы/управление пространствами)
   │  вызов через auth.client()
   ▼
stores/auth.ts (состояние аутентификации: вход/обновление/выход/токен) ── владеет токеном и логикой обновления
   │
   ▼
packages/api (Client/APIError/типы) ── единственное место, где разрешён fetch
   │
   ▼
серверный REST API (определён контрактом)
```

Принципы:

- Страницы не собирают запросы сами — всегда через `auth.client()`;
- владение токеном и обновление — в store; клиент отвечает только за отправку и повтор;
- ошибки единообразно `APIError`, распределение по `code`.

## 6. Границы страниц (продуктовое решение)

- **Web-панель = глобальное управление**: создание пространств/приглашение участников/выход — в десктопе, панель не предоставляет
  (чтобы не добавлять ещё один неописанный вход в модель прав).
- **Никакого онлайн-просмотра** (изображения/PDF/Office), файловые операции в десктоп-клиенте.
- Использование только для чтения; порог предупреждения — линия напоминания, а не лимит; **отзыв ≠ удаление** (файлы не удаляются, только заморозка+очистка участников).

## 7. Фронтенд-дисциплины (check:rules)

Админ-панель через `scripts/check-frontend-rules.mjs` принуждает к 7 дисциплинам (R1~R7):
аудитория по веткам, хранение токенов, сохранение исходного адреса охранником, тихое обновление и повтор при 401,
порядок восстановления точки входа, вызов защищённого API через клиент, запрет глобального SDK платформы.
У каждой есть обратная проверка «нарушил — красный», полные правила и последствия нарушения см. в **06-Testovaya-dokumentaciya«Фронтенд-дисциплины»**.

## 8. CI

`.github/workflows/ci.yml` при push/PR (master/main) выполняет цепочку гейтов и проверяет, что артефакт admin
можно встроить через embed; gen-csharp (модели десктопа) уже отнесён к репозиторию desktop при разделении. Полный порядок гейтов см.
в **06-Testovaya-dokumentaciya«Обзор автоматических гейтов»**.
