# Функциональный список

> Этот репозиторий = **Web-фронтенд (админ-панель)** диска NetDisk, Vue 3 + TypeScript + pnpm workspace.

## Позиционирование репозитория

| Пункт | Содержание |
|---|---|
| Название | **web** (фронтенд диска · Community-версия) |
| Характер | Vue 3 + TypeScript + pnpm workspace; единая цель сборки `admin` |
| Технологический стек | Vue 3 / Vite / Pinia / Naive UI / openapi-typescript |
| Потребитель | Артефакт после `pnpm build` копируется в серверную `internal/webui/dist/`, предоставляется через Go `embed` |
| Контракт | В этом репозитории vendored копия `DOC/api/openapi.yaml` (авторитетный источник `Doc/api/openapi.yaml`) |

**Подкаталоги**: `apps/admin`, `packages/api`, `scripts`, `DOC`.

## A. Админ-панель (`apps/admin`) — только для IT-администратора

| Страница/модуль | Файл | Функция |
|---|---|---|
| Вход | `views/LoginView.vue` + `stores/auth.ts` | Вход администратора, хранение/тихое обновление токена |
| Обзор | `views/OverviewView.vue` | Информация о текущей сессии (пользователь/роль/аудитория/request_id) |
| Пользователи и отделы | `views/UsersView.vue` | CRUD пользователей и отделов, отключение/включение, изменение ролей, повторное подтверждение |
| Управление пространствами | `views/SpacesView.vue` | Список пространств, квота/пороги предупреждения, заморозка, отзыв |
| Каркас | `layouts/AdminLayout.vue` + `router/index.ts` | Компоновка, охранники маршрутов (вход/авторизация/исходный адрес) |

> **Граница возможностей (финально)**: не выполняется никакой онлайн-просмотр (изображения / PDF / Office); просмотр и передача файлов — в десктоп-клиенте. Web-панель делает только **глобальное управление**; входы для создания пространств/приглашения участников — в десктоп-клиенте.

### Детали по страницам

- **Вход**: явный параметр `audience: "web"` (аудитория по веткам), токен в `sessionStorage`,
  единый текст при ошибке входа (без различия «пользователь не существует / неверный пароль»), отдельная подсказка при 429.
- **Обзор**: показывает только информацию о текущем вошедшем, намеренно без фейковых диаграмм данных.
- **Пользователи и отделы**: поиск/пагинация на сервере (не фильтрация на фронте), повторное подтверждение при отключении (есть внешний эффект),
  ошибка конфликта уникальности попадает в конкретное поле ввода, CRUD дерева отделов.
- **Управление пространствами**: использование только для чтения (изменяется только транзакциями загрузки/удаления), порог предупреждения — это «линия напоминания», а не лимит
  (лимит 95% — жёсткая политика сервера), **отзыв ≠ удаление** (заморозка + очистка участников, файлы не удаляются).

## B. Общая библиотека (`packages/`)

- **`packages/api`**:
  - `src/schema.gen.ts` — автоматически сгенерированные типы OpenAPI (единственный источник контракта, **не редактировать вручную**);
  - `src/index.ts` — типизированная обёртка REST-клиента (fetch/DTO/внедрение токена/тихое обновление,
    единственное место, где разрешено `fetch(`).

---

## C. Инженерные гейты (`scripts/`)

- **`lint-contract.mjs`** (`check:api` / `lint:contract`): гейт контракта — ограничивает три точки потери крови:
  рукописный fetch, рукописный DTO с тем же именем, устаревший артефакт (подробности в 06-Testovaya-dokumentaciya«Гейты контракта»).
- **`check-frontend-rules.mjs`** (`check:rules`): 7 дисциплин фронтенда (R1~R7),
  у каждой — обратная проверка (подробности в 06-Testovaya-dokumentaciya«Фронтенд-дисциплины»).
- **`gen-csharp.mjs`**: хук генерации C#-моделей для десктопа (если `desktop/` отсутствует — только проверка цепочки, выход 0).
