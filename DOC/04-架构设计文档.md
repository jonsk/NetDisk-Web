# 架构设计文档

> 记录本仓库（web 前端）的架构决策与设计约定。契约、布局、构建目标与后端强绑定。

## 1. 仓库形态

- **单构建目标的 pnpm workspace**：`apps/*` + `packages/*`。
- 社区版只保留管理后台，无 H5 工作台、无 IDP 对接、无审计日志。
- 契约 **vendor** 到本仓 `DOC/api/openapi.yaml`（权威源在服务端仓，三处需同步：
  服务端 / web / desktop）。

## 2. 技术选型（决策要点）

| 关注点 | 选型 | 理由 |
|---|---|---|
| 框架 | Vue 3（`<script setup>`） | 组合式、生态成熟 |
| 构建 | Vite 5 | 快、产物可哈希缓存 |
| 状态 | Pinia | Vue 3 官方推荐 |
| UI | Naive UI | TS 友好、按需 |
| 路由 | Vue Router 4（History） | 配合 Go SPA 回退 |
| 类型 | TS strict + vue-tsc | 类型纪律靠门禁锁住 |
| 包管理 | pnpm | workspace + 严格依赖 |
| 契约 | openapi-typescript | 单一来源生成多端模型 |
| 工具链 | node ≥ 20、pnpm ≥ 9.15.9 | CI 与本地一致 |

## 3. 部署形态（前端可嵌入）

前端**不存在独立静态服务器**：产物经 `pnpm build` 拷入服务端
`internal/webui/dist/` 目录，由 Go `embed` 提供，与 API 同源单端口。

由此产生三条**与部署强绑定**的配置（改了就白屏）：

1. **vite `base: "/admin/"`**：前端挂在子路径 `/admin`，资源引用必须以此开头，
   否则 404（白屏 + 控制台一堆 404）。
2. **`createWebHistory("/admin/")`** 与 `base` 一致；Go 侧已实现 SPA 回退。
3. **`outDir: "dist"`**：目录名不能变，否则 `go:embed` 找不到；gen 脚本把
   `web/apps/admin/dist` 拷到 `server/internal/webui/dist/admin`。

**构建顺序纪律**：先 `pnpm build` 再编译 Go —— 否则 embed 的是旧产物（静默错版）。

## 4. 契约单源机制

```
DOC/api/openapi.yaml
        │  pnpm gen:api（openapi-typescript）
        ▼
packages/api/src/schema.gen.ts   ← 生成物，禁手改
        │  pnpm check:api（lint-contract --check-generated，双向 diff）
        ▼
  即      用契约内全部模型 / 全部接口类型
```

- 类型入口 `Schema` / `Operations` / `Paths` 均来自生成物。
- `lint:contract` 三条硬约束（手写 fetch、手写同名 DTO、生成物过期）强制请求
  收敛到客户端，保证"契约单源"不被旁路（实现细节见 06-测试文档「契约门禁」）。
- `gen-csharp` 用同一份契约生成桌面端 C# 模型，保证多端理解一致。

## 5. 模块职责与分层

```
views/（页面：登录/概览/用户部门/空间治理）
   │  通过 auth.client() 调用
   ▼
stores/auth.ts（认证状态：登录/刷新/登出/令牌）── 持有令牌与刷新逻辑
   │
   ▼
packages/api（Client/APIError/类型）── 唯一允许 fetch 的地方
   │
   ▼
服务端 REST API（契约定义）
```

原则：

- 页面不直接拼请求 —— 一律走 `auth.client()`；
- 令牌持有与刷新在 store，客户端只负责发送与重放；
- 错误统一 `APIError`，按 `code` 分流。

## 6. 页面边界（产品决策）

- **Web 后台 = 全局治理**：新建空间/邀请成员/退出在桌面端，后台不提供（避免
  权限模型多出一个说不清的入口）。
- **不做任何在线预览**（看图/PDF/Office），文件操作在桌面客户端。
- 用量只读；预警阈值是提醒线不是上限；**收回≠删除**（文件不删，仅冻结+清成员）。

## 7. 前端纪律（check:rules）

管理后台通过 `scripts/check-frontend-rules.mjs` 强制 7 条纪律（R1~R7）：
分端受众、令牌存储、守卫保留原地址、401 静默刷新重放、入口恢复顺序、
受保护 API 经客户端调用、禁用平台 SDK 全局。每条均有"破坏即红"的反向验证，
完整规则与破坏后果见 **06-测试文档「前端纪律」**。

## 8. CI

`.github/workflows/ci.yml` 在 push/PR（master/main）执行门禁链并校验 admin 产物
可被 embed；gen-csharp（桌面端模型）已随拆分归属 desktop 仓。完整门禁顺序见
**06-测试文档「自动化门禁总览」**。
